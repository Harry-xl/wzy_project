# 星伴（StarPal）智能助学升级 — 产品需求文档 (PRD)

> 版本：1.1 | 日期：2026-08-02 | 状态：已确认，待开发
> 关联文档：项目文档.md, CLAUDE.md

---

## 一、背景与目标

### 1.1 项目背景

星伴（StarPal）当前版本（v0.2.6）已实现计算机网络主题的智能刷题 + AI 辅导基础功能，包括：个性化选题、能力画像、AI 题目讲解、AI 对话、错题管理等。但系统在以下方面存在明显不足：

| 维度 | 当前状态 | 差距 |
|------|---------|------|
| 知识库 | 仅有 25 个知识点标签 + 题库，无结构化知识内容 | 缺少学科知识体系 |
| AI 回答质量 | 纯 Prompt 工程，无知识检索增强 | 幻觉风险高，专业性不足 |
| 模型能力 | 直接调用 DeepSeek 通用模型 | 无领域微调，教学风格不稳定 |
| 学习路径 | 简单的 70%/30% 选题策略 | 无规划、无诊断、无资源推荐 |
| 学习陪伴 | 基础的答题统计 + AI 分析 | 无深层归因、无策略优化 |
| 知识溯源 | AI 回答无引用来源 | 学生无法验证答案正确性 |

### 1.2 产品目标

围绕学生在计算机网络专业学习中的真实痛点，构建 **"知识库 + RAG + 微调模型 + 智能体"** 四位一体的智能助学系统，实现：

1. **知识体系化**：搭建结构化计算机网络知识库，覆盖核心教材、协议标准、常见题型
2. **回答可溯源**：通过 RAG 技术，使 AI 回答基于真实知识片段，附带来源引用
3. **模型专业化**：通过领域微调，使模型输出更贴合计算机网络教学风格
4. **学习个性化**：智能诊断 → 路径规划 → 资源推送 → 效果评估的完整闭环
5. **陪伴智能化**：从"被动回答"升级为"主动辅导"，包含错题归因、策略建议、学习提醒

### 1.3 关键决策确认

> 以下决策已在 2026-08-02 与项目负责人确认，作为后续设计和开发的约束条件。

| 决策项 | 确认方案 | 影响范围 |
|--------|---------|---------|
| 知识源 | **《计算机网络》(谢希仁 第8版)** 作为核心知识源，辅以 RFC 标准文档 | 模块一：知识库内容导入 |
| 模型微调 | 优先使用 **DeepSeek 官方微调服务**（如开放）；备选开源模型自建微调 | 模块三：微调方案选型 |
| 向量存储 | **ChromaDB**（`pip install chromadb`，嵌入式运行，零配置）；MySQL 存储文本元数据，ChromaDB 存储嵌入向量 | 模块一/二：检索架构 |
| 知识点粒度 | **双层结构**：保持现有 25 个粗粒度知识点（能力画像+选题不动），新增细粒度子知识点（知识库+学习路径用） | 模块一/四：知识组织 |
| 提醒推送 | **仅前端页面内提醒**，不涉及邮件/微信等外部渠道 | 模块五：陪伴功能范围 |
| 资源推荐 | **无现有资源库**，通过 LLM 自动搜索 + 人工审核逐步建立 | 模块四：资源推荐策略 |

## 二、用户故事

### Epic 1：知识库驱动的精准问答
- **US-01**：作为学生，我希望向 AI 提问时，它能基于真实的教材/标准给出回答，并标注信息来源，这样我能信任回答的准确性。
- **US-02**：作为学生，当我做错题时，我希望 AI 讲解能引用教材中相关章节的具体内容，帮助我系统性地查漏补缺。
- **US-03**：作为管理员，我希望能够上传和管理知识文档（教材章节、RFC 标准、论文等），系统自动完成分块、嵌入和索引。

### Epic 2：个性化学习路径
- **US-04**：作为学生，我希望系统能根据我的知识掌握情况，生成一份学习计划（包含学习顺序、重点主题、预计时间），而不是随机做题。
- **US-05**：作为学生，我完成一个阶段的学习后，希望看到自己的进步曲线和下一步建议。
- **US-06**：作为学生，当我在某个知识点反复出错时，希望系统主动推送该知识点的补充材料和专项练习。

### Epic 3：深度错题归因与策略优化
- **US-07**：作为学生，我不仅想知道某题做错了，还想知道错因类型（概念混淆/计算错误/审题不清等），以及如何避免同类错误。
- **US-08**：作为学生，希望系统分析我的错题模式，告诉我"你最容易在哪些类型的题目上出错，原因是什么"。
- **US-09**：作为学生，希望获得针对我个人薄弱点的学习策略建议（如：先巩固 A 再学 B，每天做 N 道 C 类题）。

### Epic 4：学科垂类模型优化
- **US-10**：作为学生，我希望 AI 助教的讲解风格一致、专业、循序渐进，而不是时而过于简单时而过于深奥。
- **US-11**：作为系统运营者，希望通过微调模型减少 API 调用成本（微调后可用更短 prompt 达到相同效果），并提升回答的领域准确性。

### 模块一：结构化知识库 (Knowledge Base)

#### F1.1 知识文档管理

**功能描述**：构建计算机网络学科的结构化知识库，支持多类型知识源的导入、管理、版本控制。

**知识源类型**：

| 类型 | 示例 | 优先级 |
|------|------|--------|
| 教材章节 | **《计算机网络》(谢希仁 第8版)** 章节目录与核心内容 | P0 |
| 协议标准 | RFC 文档摘要（RFC 793-TCP, RFC 2616-HTTP, RFC 4271-BGP 等） | P0 |
| 知识点条目 | 25 个标准知识点的详细解释、关键概念、常见题型 | P0 |
| 典型例题 | 题库中的高质量题目 + 详细解析 | P1 |
| 学术论文 | 经典论文核心观点（TCP 拥塞控制、SDN 等） | P2 |
| 实验/实践 | Wireshark 抓包分析、Socket 编程示例 | P2 |

**数据模型（新增表）**：

```sql
-- 知识库文档表
CREATE TABLE knowledge_documents (
    doc_id          INT AUTO_INCREMENT PRIMARY KEY,
    title           VARCHAR(500) NOT NULL COMMENT '文档标题',
    doc_type        ENUM('textbook','rfc','knowledge_entry','problem_solution','paper','lab','other') NOT NULL,
    knowledge_points VARCHAR(1000) COMMENT '关联知识点（JSON数组）',
    osi_layer       VARCHAR(50) COMMENT '关联OSI层级',
    difficulty      ENUM('基础','进阶','高级') DEFAULT '基础',
    source          VARCHAR(500) COMMENT '来源（书名/RFC编号/URL）',
    source_page     VARCHAR(100) COMMENT '来源页码/章节号',
    version         INT DEFAULT 1 COMMENT '版本号',
    status          ENUM('draft','published','archived') DEFAULT 'draft',
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_doc_type (doc_type),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='知识库文档元数据表';

-- 知识块表（RAG检索的基本单元）
CREATE TABLE knowledge_chunks (
    chunk_id        INT AUTO_INCREMENT PRIMARY KEY,
    doc_id          INT NOT NULL,
    chunk_index     INT NOT NULL COMMENT '块在文档中的序号',
    content         MEDIUMTEXT NOT NULL COMMENT '文本内容',
    content_hash    VARCHAR(64) COMMENT '内容哈希（用于增量更新检测）',
    token_count     INT COMMENT 'Token 估算数',
    embedding       JSON COMMENT '文本嵌入向量（JSON数组格式）',
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (doc_id) REFERENCES knowledge_documents(doc_id) ON DELETE CASCADE,
    INDEX idx_doc_chunk (doc_id, chunk_index)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='知识块表——RAG检索的最小单元';

-- 知识关系表（知识图谱）
CREATE TABLE knowledge_relations (
    relation_id     INT AUTO_INCREMENT PRIMARY KEY,
    source_kp       VARCHAR(200) NOT NULL COMMENT '源知识点',
    target_kp       VARCHAR(200) NOT NULL COMMENT '目标知识点',
    relation_type   ENUM('prerequisite','extension','related','part_of') NOT NULL,
    description     VARCHAR(500) COMMENT '关系说明',
    INDEX idx_source (source_kp),
    INDEX idx_target (target_kp)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='知识点关系图';

-- 子知识点表（细粒度，用于知识库组织和学习路径）
CREATE TABLE knowledge_sub_topics (
    sub_topic_id    INT AUTO_INCREMENT PRIMARY KEY,
    sub_topic_name  VARCHAR(200) NOT NULL COMMENT '子知识点名称',
    parent_kp       VARCHAR(200) NOT NULL COMMENT '所属粗粒度知识点（对应25个标准知识点）',
    description     TEXT COMMENT '子知识点简介',
    sort_order      INT DEFAULT 0 COMMENT '建议学习顺序',
    UNIQUE KEY uq_sub_topic (sub_topic_name, parent_kp),
    INDEX idx_parent (parent_kp)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='子知识点表——细粒度知识组织';
```

**双层知识点架构**（解决粒度冲突）：

```
粗粒度（25个，现有ability_profile + 选题推荐，不动）
    │
    │  1:N 映射
    │
细粒度（~80-100个子知识点，知识库分块 + 学习路径，新增）
```

| 粗粒度知识点（现有，25个） | 子知识点（新增，示例） |
|---|---|
| TCP连接管理 | 三次握手机制、四次挥手机制、TCP状态转换图、SYN泛洪攻击 |
| TCP可靠传输与流量控制 | 序列号与确认号、滑动窗口协议、选择重传SR、零窗口探测 |
| TCP拥塞控制 | 慢启动、拥塞避免、快重传、快恢复、Tahoe/Reno/CUBIC对比 |
| IP地址与子网划分 | 分类编址(A/B/C类)、子网掩码计算、CIDR无类编址、VLSM可变长子网、路由聚合 |
| 路由算法与协议 | 距离矢量算法、链路状态算法、RIP协议详解、OSPF协议详解、BGP协议详解 |
| HTTP与HTTPS | HTTP/1.1持久连接、HTTP/2多路复用、HTTPS TLS握手、HTTP缓存策略、Cookie与Session |
| DNS系统 | DNS解析流程、DNS记录类型、DNS缓存与TTL、DNS安全(DNSSEC) |
| ... | ... |

> **设计原则**：粗粒度知识点保持不变，确保现有 `ability_profile` 表、`exam.py` 选题逻辑、前端画像展示**零影响**。子知识点仅用于：(1) 知识库文档的精准分类和检索，(2) 学习路径的精细排序，(3) 错题归因的精准定位。学习路径中的子知识点完成后，其熟练度加权映射回上层粗粒度知识点。

**功能点**：
- [ ] F1.1.1 知识文档 CRUD（创建/读取/更新/删除），含状态管理
- [ ] F1.1.2 文档自动分块（按段落/标题/固定 Token 数分块，支持重叠窗口）
- [ ] F1.1.3 文本嵌入生成（调用 DeepSeek Embedding API 或开源嵌入模型）
- [ ] F1.1.4 知识块检索 API（语义检索 + 关键词检索混合）
- [ ] F1.1.5 知识关系图谱维护（前置知识/扩展知识/相关知识）
- [ ] F1.1.6 批量导入（支持 Markdown、TXT、PDF、DOCX 格式）

#### F1.2 知识检索服务

**功能描述**：提供高效的知识检索能力，支撑 RAG 问答和学习资源推荐。

**检索流程**：
```
用户查询 → 查询嵌入 → 向量相似度检索（Top-K）→ 关键词BM25检索 → 
混合排序（RRF融合） → 返回相关知识块 + 来源信息
```

**技术方案**：
- **向量存储**：**ChromaDB**（`pip install chromadb`，嵌入式运行，零配置，无需单独安装服务）。ChromaDB 仅存储嵌入向量 + 块 ID，文本内容和元数据仍存在 MySQL `knowledge_chunks` 表中。检索时 ChromaDB 返回 Top-K 块 ID → MySQL 查询文本内容。
- **与现有 MySQL 的关系**：互补而非替代。MySQL 继续负责所有现有数据（用户、题目、答题记录）和新增的知识文档元数据、知识块文本；ChromaDB 仅负责向量相似度检索。两者通过 `chunk_id` 关联。
- **嵌入模型**：DeepSeek Embedding API 或 `text-embedding-3-small`
- **混合检索**：语义检索（ChromaDB 向量相似度）+ 关键词检索（MySQL 全文索引）→ RRF (Reciprocal Rank Fusion) 融合排序

**API 设计**：
```
GET /api/knowledge/search
  参数: q (查询文本), top_k (默认5, 最大20), doc_type (可选过滤)
  返回: { chunks: [{ content, doc_title, source, score, knowledge_points }] }
```

### 模块二：检索增强生成 (RAG)

#### F2.1 RAG 问答引擎

**功能描述**：改造现有 AI 对话和讲解接口，在调用 LLM 前先检索相关知识块，将知识上下文注入 Prompt，实现"检索 → 增强 → 生成"流水线。

**RAG 流水线**：
```
用户提问
    │
    ▼
┌──────────────┐
│ 1. 查询重写   │ ← 将用户口语化问题改写为检索友好形式（可选，LLM辅助）
└──────┬───────┘
       ▼
┌──────────────┐
│ 2. 知识检索   │ ← 向量检索 + 关键词检索 → Top-K 知识块
└──────┬───────┘
       ▼
┌──────────────┐
│ 3. 相关性过滤  │ ← 过滤相似度低于阈值的结果，去重
└──────┬───────┘
       ▼
┌──────────────┐
│ 4. 上下文组装  │ ← 将知识块 + 来源信息组装为结构化 Prompt
└──────┬───────┘
       ▼
┌──────────────┐
│ 5. LLM 生成   │ ← 调用 DeepSeek（或微调模型）生成回答
└──────┬───────┘
       ▼
┌──────────────┐
│ 6. 来源标注   │ ← 在回答中附加知识来源引用
└──────────────┘
```

**Prompt 模板设计**：
```
【系统指令】
你是星伴（StarPal）的计算机网络专业助教。请基于以下【参考资料】回答用户问题。
- 如果参考资料包含答案，请基于资料回答并标注来源。
- 如果参考资料不充分，请基于你的专业知识补充，并明确标注"以下内容基于通用知识，非参考资料"。
- 回答结构：要点概览 → 详细解释 → 示例 → 来源引用

【参考资料】（来自知识库检索）
[1] 《计算机网络》(谢希仁) 第5章 - 传输层
    TCP 提供面向连接的、可靠的数据传输服务。它通过序列号、确认应答、重传机制来保证可靠性...
[2] RFC 793 - Transmission Control Protocol
    The TCP must recover from data that is damaged, lost, duplicated, or delivered out of order...
...

【用户问题】
{user_message}

【回答要求】
请用中文回答，结构化组织内容，必要时使用表格或对比。
```

**改造范围**：

| 现有接口 | 改造方式 |
|---------|---------|
| `POST /api/chat` | 增加 RAG 检索步骤，注入知识上下文；增加 `use_rag` 参数（默认 true） |
| `POST /api/explain` | 检索题目关联知识点对应的知识块，注入讲解 Prompt |
| `POST /api/explain/stream` | 同上，流式场景先检索再流式生成 |

#### F2.2 可溯源回答

**功能描述**：AI 回答中自动附带知识来源引用，学生可点击查看原文片段。

**来源标注格式**（Markdown）：
```markdown
## TCP 三次握手

TCP 建立连接需要三次握手过程...

> 📚 **参考来源**：
> - [1] 《计算机网络》(谢希仁 第7版) · 第5章 传输层 · 5.2.1 TCP连接建立
> - [2] RFC 793 · Section 3.4 · Establishing a connection
```

**前端展示**：
- 在 Markdown 渲染中，引用块使用特殊样式（左侧边框 + 📚 图标）
- 来源编号可点击，展开显示知识片段原文
- 对话历史中保存来源引用，支持回溯查看

### 模块三：模型微调 (Model Fine-tuning)

#### F3.1 微调数据准备

**功能描述**：从现有数据和知识库中构建高质量的领域微调数据集。

**微调数据来源**：

| 数据类型 | 来源 | 预估规模 | 优先级 |
|---------|------|---------|--------|
| 题目讲解对 | `user_answers` + `problems` → 构造 (题目+答案 → 详细讲解) 对 | ~500 对 | P0 |
| 知识问答对 | 知识库内容 → 自动生成 (知识片段 → 问答对) | ~1000 对 | P0 |
| 对话记录 | AI 对话日志中筛选高质量多轮对话 | ~200 组 | P1 |
| 错题分析对 | (错题+学生答案+正确率) → (错题 → 归因分析) | ~300 对 | P1 |
| 学习建议对 | (能力画像 → 学习建议) 模板化生成 | ~200 对 | P2 |

**数据格式**（Alpaca/ShareGPT 格式）：
```json
{
  "instruction": "你是一位计算机网络专业助教。请为以下题目提供详细的逐步讲解。",
  "input": "题目：TCP 三次握手的过程是什么？\n知识点：TCP连接管理\n难度：中等\n正确答案：SYN → SYN-ACK → ACK",
  "output": "## 考查知识点与思路\n\n本题考察 TCP 连接管理中的三次握手（Three-Way Handshake）机制...\n\n## 详细解题步骤\n\n### 第一步：客户端发送 SYN\n..."
}
```

**数据集构建流程**：
```
原始数据采集 → 数据清洗（去重、过滤低质量） → 
模板化构造 → 人工/LLM质量审核 → 
训练/验证/测试集切分（8:1:1） → 格式转换（Alpaca/ShareGPT）
```

#### F3.2 LoRA 微调方案

**功能描述**：使用 LoRA (Low-Rank Adaptation) 技术对 DeepSeek 模型进行轻量化微调。

**技术方案**（优先使用 DeepSeek 微调服务）：

**阶段一：Prompt 优化（当前即可做）**
- 基于知识库优化系统 Prompt 模板
- A/B 测试不同 Prompt 策略的回答质量
- 成本：零

**阶段二：DeepSeek 官方微调（中期，推荐）**
- 使用 DeepSeek 平台提供的模型微调服务（如开放）
- 上传构造好的训练数据集 → 平台自动训练 → 返回微调后的模型端点
- 优势：无需自建 GPU 环境、无需维护训练基础设施、与现有 API 调用方式兼容
- 成本：按训练 Token 量计费

**阶段三：自建微调（备选，如 DeepSeek 微调服务不可用）**
- 基座模型：Qwen-2.5-7B-Instruct 或 DeepSeek-V2-Lite
- 工具：LLaMA-Factory / Hugging Face PEFT + LoRA
- 需要：单卡 A100/4090 GPU（可租用云 GPU）

**LoRA 训练参数建议**：
```
- base_model: Qwen-2.5-7B-Instruct 或 DeepSeek-V2-Lite
- lora_rank (r): 16
- lora_alpha: 32
- lora_target: q_proj, v_proj, k_proj, o_proj
- learning_rate: 2e-4
- epochs: 3
- batch_size: 4 (gradient_accumulation: 4)
- cutoff_len: 2048
```

#### F3.3 模型评估体系

**评估维度**：

| 维度 | 指标 | 方法 |
|------|------|------|
| 专业准确性 | 事实正确率 | 领域专家抽检 / LLM-as-Judge |
| 教学有效性 | 讲解清晰度、步骤完整性 | 学生评分 + LLM-as-Judge |
| 安全性 | 有害内容率 | 安全评估集测试 |
| 一致性 | 相同问题多次回答的一致性 | 重复采样 |
| 响应效率 | 首 Token 延迟、总生成时间 | 性能测试 |

### 模块四：智能学习路径规划

#### F4.1 知识诊断引擎

#### F4.2 学习路径生成

**功能描述**：基于知识图谱 + 能力画像，动态生成个性化学习路径。

**路径生成算法**：
```
输入：用户能力画像、知识图谱（prerequisite关系）、学习目标
输出：有序学习路径 + 每阶段资源推荐

步骤：
1. 找出未掌握的知识点（熟练度 < 0.6）
2. 按知识图谱中的 prerequisite 关系拓扑排序
3. 优先推荐"前置知识已掌握、当前知识薄弱"的节点
4. 为每个节点分配：推荐题目数、推荐阅读材料（知识库）、预计学习时间
5. 生成阶段性里程碑和预计完成日期
```

**学习路径结构**：
```json
{
  "path_id": "path_xxx",
  "user_id": 1,
  "created_at": "2026-08-02",
  "target": "全面掌握传输层知识",
  "estimated_days": 14,
  "stages": [
    {
      "order": 1,
      "knowledge_point": "UDP协议",
      "reason": "UDP 是理解 TCP 的前置知识，且你已部分掌握（熟练度 0.55）",
      "tasks": [
        {"type": "read", "title": "UDP 协议概述", "doc_id": 10, "estimated_minutes": 15},
        {"type": "practice", "count": 8, "difficulty": "简单"},
        {"type": "quiz", "count": 3, "difficulty": "中等"}
      ],
      "milestone": "UDP 熟练度达到 0.75"
    },
    {
      "order": 2,
      "knowledge_point": "TCP可靠传输与流量控制",
      "reason": "核心知识点，你当前熟练度仅 0.3",
      "prerequisites": ["UDP协议"],
      "tasks": [...]
    }
  ]
}
```

**API 设计**：
```

  参数: user_id, target (可选), days_available (可选)
  返回: { path_id, stages, estimated_days, ... }

GET /api/learning_path/<user_id>
  返回: 当前激活的学习路径及完成进度
```

#### F4.3 学习资源推荐

**功能描述**：在现有"仅推荐题目"基础上，扩展为多类型资源推荐。

**推荐资源类型**：
- 📖 **知识阅读**：知识库中的教材章节、标准文档（已有，直接推荐）
- 📝 **专项练习**：指定知识点/难度的题目（已有，直接推荐）
- 🔍 **智能搜索推荐**：通过 LLM 根据知识点自动搜索和推荐外部学习资料（B站/慕课/技术博客等），标注来源链接，由管理员审核后逐步入库
- 🔧 **实践任务**：Wireshark 实验、Socket 编程练习（知识库中预置）

**推荐策略**：
```
当前学习阶段 → 弱点知识点 →
  ├── 必推：知识库对应章节阅读 + 15 道专项练习题
  ├── 搜索推荐：LLM 生成该知识点的外部资源搜索建议（关键词 + 推荐理由）
  └── 挑战：1-2 道高难度综合题（如熟练度已 > 0.6）
```

> **说明**：由于当前无现成资源库，外部资源推荐采用"LLM 生成搜索建议"模式——系统为每个知识点预生成搜索关键词和推荐理由，学生在页面点击后跳转到对应平台搜索，而非直接提供链接（避免死链和维护负担）。知识库内部资源（教材章节、RFC）直接推荐。

### 模块五：智能学习陪伴

#### F5.1 学习提醒与督促

**功能描述**：基于学习数据分析，主动推送学习提醒。

**提醒触发条件**：

| 条件 | 提醒内容 |
|------|---------|
| 超过 3 天未学习 | "你已经 3 天没有练习了，建议今天做 10 道题保持手感" |
| 学习路径进度落后 | "你的学习路径预计还需要 7 天完成，按当前速度可能需要 12 天" |
| 某知识点连续答错 ≥3 次 | "你在「TCP拥塞控制」上连续错了 3 次，建议先阅读相关知识点再练习" |
| 实力明显下降 | "最近一周你的答题正确率下降了 15%，是否需要调整学习策略？" |
| 达成了里程碑 | "恭喜！你已完成传输层所有知识点的学习 🎉" |

**实现方式**：
- 前端 Dashboard 首页添加「学习动态」卡片
- 登录时检查并显示未读提醒（调用 `/api/notifications/<user_id>` 接口）
- 提醒数据在后端计算，前端轮询获取（或登录时一次性拉取）
- 范围限定：仅前端页面内提醒，不涉及邮件/微信等外部渠道

#### F5.2 深度错题归因分析

**功能描述**：从"判对错"升级为"找原因、给策略"。

**归因分析流程**：
```
学生答错 → 
  1. LLM 分析：对比学生答案与正确答案 → 判断错因类型
  2. 统计分析：聚合该学生所有错题的归因分布
  3. 策略生成：根据归因模式推荐针对性训练方案
```

**归因报告示例**：
```
📊 你的错题归因分析（最近 30 天）

| 错因类型 | 占比 | 趋势 |
|---------|------|------|
| 概念混淆 | 45% | ↑ 上升 |
| 计算错误 | 25% | → 持平 |
| 审题不清 | 20% | ↓ 下降 |
| 知识遗忘 | 10% | → 持平 |

💡 建议：
- 你最容易因概念混淆而出错，建议重点梳理相似概念的对比（如 TCP vs UDP, OSPF vs BGP）
- 「IP子网划分」的计算题需要加强练习
```

#### F5.3 导师/学伴智能体

**功能描述**：在现有"计算机网络助教"角色基础上，增加多种智能体角色。

**智能体类型**：

| 角色 | 触发场景 | 行为特征 |
|------|---------|---------|
| 🧑‍🏫 **导师模式**（现有） | 知识问答、题目讲解 | 结构化讲解，逐步引导，注重理解 |
| 🧑‍🎓 **学伴模式** | 日常练习陪伴 | 鼓励式语气，一起做题，讨论思路 |

**实现方式**：

- 前端聊天界面可切换角色（下拉选择）
- 角色切换时自动调整对话风格和输出格式
