## 2. 背景与问题

### 2.1 Phase 2 做了什么

```
上传 PDF → OCR 提取 → 分块 → 向量化 → ChromaDB → ✅ AI 引用
                          ↓
                    知识点映射 → ✅ 覆盖度图表 (知识图谱/覆盖率)
```

**两条链路都通了，但都止步于"元数据级别"。**

### 2.2 三大核心矛盾

#### 矛盾 1：资料库对 AI 可用，但对人不可用

资料以 OCR 碎片 chunks 形态存储，用户看到的是杂乱的原始文本——无排版、无图片表格、无学习结构。**资料只有"被 AI 引用"这一个出口。**

#### 矛盾 2：两套知识点体系，学练割裂

```
题库体系 (problems / ability_profile)        知识库体系 (knowledge_sub_topics)
─────────────────────────────────         ─────────────────────────────────
knowledge_point VARCHAR(100) 自由文本      双层结构: sub_topic → parent_kp
"TCP连接管理" "IP地址与子网划分"            71 个子知识点，25 个粗粒度知识点
                                          + 55 条知识关系 (prerequisite/related/...)
    │                                           │
    ├─ 选题策略 (exam.py)                        ├─ 知识点映射 (knowledge_mapper.py)
    ├─ 能力画像 (Ability_Profile.py)              ├─ 知识图谱 (ECharts force graph)
    └─ 错题管理                                  └─ 知识清单 (覆盖度表格)

              ← ← ← 两套体系互不关联 → → →
```

**具体症状：**
- 用户做错了"TCP拥塞控制"的题目 → 不知道资料库里有哪些资料可以学习这个知识点
- 用户在知识图谱中看到"TCP拥塞控制"覆盖度低 → 不知道题库里有没有相关题目可以练习
- 能力画像显示"UDP协议"熟练度 0.3 → 无法一键跳转到这个知识点的学习卡片

#### 矛盾 3：测试数据与主题不匹配

当前测试数据是 **C 语言题**（`C语言基础`、`指针`、`链表`等 9 个知识点），与项目定位的**计算机网络**主题完全不一致。

## 4. 基础层：统一知识点体系

> **这是所有上层能力（学习卡片、学练打通）的基础。必须先做。**

### 4.1 现状对比

| 维度 | 题库体系 | 知识库体系 |
|------|---------|-----------|
| 字段 | `problems.knowledge_point VARCHAR(100)` | `knowledge_sub_topics.parent_kp VARCHAR(200)` |
| | `ability_profile.knowledge_point VARCHAR(100)` | `knowledge_sub_topics.sub_topic_name VARCHAR(200)` |
| 粒度 | 粗粒度文本，无层级 | 双层：25 粗粒度 + 71 子知识点 |
| 关系 | 无 | 55 条关系（前置/扩展/相关/组成） |
| 值来源 | 人工填写，自由文本 | 种子数据导入，结构化 |
| 当前值 | C 语言相关（与主题不匹配） | 计算机网络（与主题匹配） |

### 4.2 统一方案

#### 方案选择：题库 knowledge_point 对齐到 parent_kp（25 个粗粒度知识点）

**为什么选择 parent_kp 而非 sub_topic？**
- 一道题通常覆盖一个粗粒度知识点（如"TCP连接管理"），而非某个子知识点（如"三次握手机制"）
- 与现有选题策略和画像算法的输入粒度匹配
- 如果需要细粒度，后续可通过 `sub_topic_id` 可选字段扩展

#### 迁移步骤

**Step 1: 添加约束（不改现有功能）**

```sql
-- 在 knowledge_sub_topics 的 parent_kp 上创建唯一索引（实际上已有 idx_parent）
-- 在 problems 表添加外键约束（可选，先做软约束）
-- 核心是保证 problems.knowledge_point 的值在 parent_kp 集合内
```

**Step 2: problems 表扩展（新增字段）**

```sql
ALTER TABLE problems
ADD COLUMN sub_topic_id INT DEFAULT NULL COMMENT '关联的子知识点ID（可选，精确映射）',
ADD FOREIGN KEY (sub_topic_id) REFERENCES knowledge_sub_topics(sub_topic_id) ON DELETE SET NULL,
ADD INDEX idx_sub_topic (sub_topic_id);
```

保留现有 `knowledge_point VARCHAR(100)` 字段不变（向后兼容），但约定其值必须是 `knowledge_sub_topics.parent_kp` 的有效值。新增 `sub_topic_id` 为可选精确映射。

**Step 3: ability_profile 扩展**

```sql
-- 现有 knowledge_point VARCHAR(100) 保持不变
-- 新增可选的 parent_kp 精确引用（向后兼容，渐进迁移）
ALTER TABLE ability_profile
ADD COLUMN parent_kp_ref VARCHAR(200) DEFAULT NULL COMMENT '引用的标准知识点名称（与knowledge_sub_topics.parent_kp对齐）',
ADD INDEX idx_parent_kp (parent_kp_ref);
```

**Step 4: 数据迁移 — 替换测试数据**

将现有 C 语言测试题替换为计算机网络题，knowledge_point 使用 parent_kp 的有效值：

```sql
-- 示例：新题目数据
INSERT INTO problems (problem_num, problem, answer, difficulty, knowledge_point, sub_topic_id) VALUES
('NET001', 'TCP三次握手中，第三次握手报文段的SYN标志位为？\nA. 1\nB. 0', 'B', '简单', 'TCP连接管理', (SELECT sub_topic_id FROM knowledge_sub_topics WHERE sub_topic_name='三次握手机制')),
('NET002', '以下哪项不是TCP拥塞控制算法？\nA. 慢启动\nB. 快重传\nC. Dijkstra\nD. 拥塞避免', 'C', '中等', 'TCP拥塞控制', (SELECT sub_topic_id FROM knowledge_sub_topics WHERE sub_topic_name='Tahoe/Reno/CUBIC对比')),
-- ...更多题
```

**Step 5: 选题策略适配（`AI_operate/exam.py`）**

现有代码已支持按 `knowledge_point` 筛选：
```python
# 现有逻辑（无需改动 SQL）
if knowledge_points:
    placeholders = ", ".join(["%s"] * len(knowledge_points))
    sql.append(f"AND p.knowledge_point IN ({placeholders})")
```

只需确保传入的 `knowledge_points` 值是 parent_kp 列表即可。**代码逻辑不变，仅数据层面对齐。**

**Step 6: 能力画像适配（`AI_operate/Ability_Profile.py`）**

现有代码使用 `knowledge_point` 做画像维度和统计分析。对齐后工作方式不变，但值域从随意文本变为标准 parent_kp。**一个关键改进：画像现在可以和知识库的覆盖度叠加对比。**

## 5. 用户故事

### 5.1 基础层 — 统一知识点体系

- **US-Z01**: 作为**系统**，题库的 `knowledge_point` 取值与知识库的 `parent_kp` 保持一致，以便**题目和资料可以通过知识点关联起来**

- **US-Z02**: 作为**学生**，我看到的题目知识点标签和知识库知识点名称是**同一套标准名称**，以便**不会困惑"为什么这里叫TCP连接管理，那里叫TCP协议"**

### 5.2 能力 C — 学习呈现 (Phase 2.5 MVP)

- **US-C01** (学习卡片-精简): 作为学生，我希望**点击知识点时默认看到精简版卡片**（定义 + 3~5个关键要点 + 来源出处），以便**快速浏览核心内容**

- **US-C02** (学习卡片-完整): 作为学生，我希望**点击"展开详细"后看到 AI 生成的完整讲解**（详细解释 + 常见误区 + 记忆方法 + 关联知识点链接 + 典型考题），以便**深入全面学习**

- **US-C03** (学习卡片-溯源): 作为学生，我希望**在学习卡片底部看到原始资料片段**，以便**验证 AI 生成内容的准确性**

- **US-C04** (资料正文阅读): 作为学生，我希望**点击某份资料后看到 AI 整理过的可读正文**（按章节组织、有目录、图表位置有文字描述占位），以便**像阅读电子书一样浏览资料**

### 5.3 能力 D — 学练打通 (Phase 2.5)

- **US-D01** (做题→查资料): 作为学生，我希望**做题时题目下方显示"📚 查看学习资料"按钮**，点击后跳转到该知识点对应的学习卡片（或知识库资料），以便**做错题后能立即找到对应的学习材料**

- **US-D02** (看资料→练题): 作为学生，我希望**在学习卡片底部看到"📝 练习相关题目"按钮**，点击后跳转到做题界面并**自动筛选该知识点的题目**，以便**学完立即检验掌握程度**

- **US-D03** (画像→学习): 作为学生，我希望**在能力画像中点击某个薄弱知识点**（熟练度 < 0.6），弹出菜单包含"📖 学习资料"和"📝 针对性练习"，以便**发现薄弱环节后立即采取行动**

- **US-D04** (知识图谱→练题): 作为学生，我希望**在知识图谱中点击节点后，除了学习卡片，还能看到"🎯 练习此知识点"按钮**，以便**从知识覆盖视角直接进入刷题**

#### C1. 知识点学习卡片（核心）

**新增表 `knowledge_learning_cards`：**
```sql
CREATE TABLE knowledge_learning_cards (
    card_id         INT AUTO_INCREMENT PRIMARY KEY COMMENT '卡片ID',
    sub_topic_id    INT NOT NULL COMMENT '关联的子知识点ID',
    user_id         INT DEFAULT NULL COMMENT 'NULL=系统级卡片，非NULL=个人资料卡片',
    
    slim_content    JSON COMMENT '精简版内容 {definition, key_points[], source_docs[]}',
    full_content    MEDIUMTEXT COMMENT '完整版Markdown内容',
    
    source_chunk_ids JSON COMMENT '引用的chunk ID列表',
    generation_model VARCHAR(100) COMMENT '生成模型',
    
    slim_generated_at   TIMESTAMP NULL,
    full_generated_at   TIMESTAMP NULL,
    is_regenerating     TINYINT(1) DEFAULT 0,
    
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    UNIQUE KEY uq_card_topic_user (sub_topic_id, user_id),
    FOREIGN KEY (sub_topic_id) REFERENCES knowledge_sub_topics(sub_topic_id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES user(user_id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### C2. 资料正文阅读器（纯 AI 整理）

> 用户选择：不使用原始 PDF 页面并排，而是让 AI 把 OCR 碎片整理成可读 Markdown。

**处理流程：**
```
选中资料 → 点击「阅读」
  → 有缓存？→ 直接渲染 Markdown
  → 无缓存？→ AI 整理：
      合并段落、识别标题层级、生成目录树
      原图/表格插入描述占位符："[📊 此处有TCP/UDP对比表，包含...]"
      → 写入缓存 → 前端 Markdown 渲染
```

#### D1. 学练打通 — 四个交叉入口

**入口 1: 做题页 → 学习资料**
```
题目展示区域
┌─────────────────────────────────────┐
│ TCP三次握手中，第三次握手报文段...    │
│ A. SYN=1  B. SYN=0  C. ...         │
│                                     │
│ [提交答案]                           │
│                                     │
│ 📚 知识点：TCP连接管理 → [查看学习资料] │  ← 新增
└─────────────────────────────────────┘
```
- 实现：`exam.html` 或 `dashboard.html` 内嵌 exam iframe 中，根据当前题目的 `knowledge_point` 生成链接
- 点击 → 打开学习卡片 Modal（复用组件）
- 参数传递：通过 `postMessage` 或 URL query string

**入口 2: 学习卡片 → 练题**
- 学习卡片底部的 `[📝 练习相关题目]` 按钮
- 点击 → 切换到做题 section → 携带 `knowledge_points=[当前知识点parent_kp]`
- 利用现有 `get_personalized_problems(knowledge_points=[...])` 接口
- 进入"针对性练习模式"（顶部提示："正在练习：TCP连接管理"）

**入口 3: 能力画像 → 学习/练题**
- 能力画像中的知识点列表，每个薄弱项（熟练度 < 0.6）右侧新增操作按钮
- 可选操作：`📖 学习` → 打开学习卡片 / `📝 练习` → 针对性刷题

**入口 4: 知识图谱 → 练题**
- 知识图谱节点点击后弹出的面板中，除学习卡片外，新增 `[🎯 练习此知识点]` 按钮

## 9. 依赖与风险

| 类型 | 描述 | 缓解措施 |

| **延迟风险** | 完整版卡片生成 20-40s | SSE 流式输出，用户边看精简版边等 |
