## 发布前检查

### 代码质量
- [ ] `python -m pytest tests/ -v` — 全部测试通过
- [ ] `python -m pytest tests/ --cov` — 覆盖率达到目标
- [ ] 代码审查完成（审查清单已签署）
- [ ] 无已知阻塞级 Bug
- [ ] 所有 TODO/FIXME 已处理或转为 Issue

### 安全
- [ ] `.env` 文件中为生产环境密钥（非开发密钥）
- [ ] 无硬编码密钥、密码、Token
- [ ] DeepSeek API Key 配额充足
- [ ] CORS 限制为生产域名（非 `*`）
- [ ] Flask DEBUG = false

### 数据库
- [ ] 所有迁移已在生产数据库执行
- [ ] 数据库已备份（`mysqldump` 或等效操作）
- [ ] 数据清理任务配置正确（保留天数合理）

### 文档
- [ ] `docs/api-reference.md` 与代码一致
- [ ] `docs/database-schema.md` 与生产库一致
- [ ] `changelog.md` 已更新本版本变更
- [ ] `CLAUDE.md` 反映最新项目结构

### 功能验证（冒烟测试）
- [ ] 注册新用户 → 成功
- [ ] 登录 → 成功
- [ ] 游客随机做题 → 正常
- [ ] 登录用户个性化做题 → 正常
- [ ] 答案提交 + 判题 → 正确
- [ ] 能力画像查看 → 数据显示正常
- [ ] AI 流式讲解 → 打字机效果正常
- [ ] AI 对话 → 多轮对话正常
- [ ] 错题浏览 + 重做 → 功能正常
- [ ] 管理后台 CRUD → 正常
- [ ] 静态资源加载正常（CSS/JS/图片）

## 发布步骤

1. [ ] 合并 feature/bugfix 分支到 main
2. [ ] 打版本标签：`git tag -a vX.Y.Z -m "版本 X.Y.Z: 变更摘要"`
3. [ ] 推送代码和标签
4. [ ] 部署到目标环境
5. [ ] 执行冒烟测试
6. [ ] 监控异常日志（持续 24h）

---

## 发布后

- [ ] 观察错误日志（重点：LLM API 调用、数据库查询）
- [ ] 观察用户反馈（如有反馈渠道）
- [ ] 如有紧急问题 → 创建 hotfix 分支

---

## 回滚方案

如发布后出现严重问题：
1. [ ] 切回上一版本标签
2. [ ] 如有数据库变更 → 执行回滚迁移
3. [ ] 通知相关用户（如有必要）
4. [ ] 分析根因 → 创建 postmortem 文档
