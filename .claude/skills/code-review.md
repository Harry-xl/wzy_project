# Skill: 代码审查 (code-review)

> 系统化的代码审查流程，覆盖安全、正确性、性能、风格、文档、测试 6 个维度

## 工作流程

### 第一步：确定审查范围
1. 通过 `git diff` 或指定文件/文件夹确定审查范围
2. 了解本次变更的目的（功能添加/Bug修复/重构）

### 第二步：逐维度检查

按 `.claude/templates/code-review-checklist.md` 的清单进行：

1. **安全**：无硬编码密钥、SQL 参数化、输入验证、错误信息不泄露内部细节
2. **正确性**：所有路径有测试、边界条件处理、事务正确、资源正确释放
3. **性能**：数据库查询使用索引、无 N+1 查询、大结果集分页、DOM 批量更新
4. **风格**：PEP 8 / ES6+ 规范、类型提示、命名一致、无废弃代码
5. **文档**：新 API 已记录、复杂逻辑有注释（中文 OK）、结构变更已反映
6. **测试**：单元测试覆盖业务逻辑、集成测试覆盖 API、外部 API 已 Mock

### 第三步：输出审查报告
```markdown
## 代码审查报告

### 审查范围
- 文件: xxx
- 变更类型: 功能添加

### 发现问题
| 严重度 | 文件 | 问题 | 建议 |
|--------|------|------|------|
| 高 | xxx.py:42 | 硬编码密钥 | 改用环境变量 |

### 审查结论
- [ ] 阻塞：存在高危问题，必须修复后才能合并
- [ ] 条件通过：存在低危问题，建议修复后合并
- [ ] 通过：未发现问题
```
